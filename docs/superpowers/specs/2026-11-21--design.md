# Specification: ColabTerm Android MVP

## Goal

Create a standalone Android APK with a minimal Termux-style command-line interface, focused on running Google Colab CLI commands. The command parsing/control core is written in Rust; the Android UI is written in Java; Python embedded in the APK invokes an Android-compatible Google Colab CLI source.

## Initial scope

- Dark terminal screen, monospace text, command history, scrolling logs, and command input.
- Run only `colab` and subcommands on the allowlist; do not pass user strings to `/bin/sh` and do not simulate a general-purpose Linux shell.
- Bundle the Android `google-colab-cli` fork, version `0.7.2.post0+android5.3`, with Chaquopy/Python 3.13. The fork replaces native/problematic dependencies with pure-Python adapters; its source and license remain in `third_party/google-colab-cli-android/`.
- Allow Colab commands that do not require PTY, such as `help`, `version`, `sessions`, `status`, `new`, `exec`, `run`, `stop`, `ls`, `upload`, `download`, `install`, and `log`.
- Store the OAuth token with Android Keystore AES-GCM through the Java/Python bridge; on Android, do not read/write `~/.config/colab-cli/token.json`.
- Target ARM64 devices; add an emulator ABI only if the build and dependencies permit it.

## Out of scope / limitations

- Do not provide a rootfs or a general shell toolset like Termux.
- Interactive PTY/SSH commands (`console`, `repl`, `ssh`) are not yet supported; report an error rather than hanging or simulating success.
- The keep-alive daemon that uses Linux CLI subprocesses is disabled on Android; a Colab session may expire when the system suspends or closes the app.
- Do not create Colab sessions, call OAuth, use T4, or send data during build/test.
- The fork reports that it runs on Termux, but it has not been verified in Chaquopy/APK or on a real Android device; do not claim those components have run successfully.

## Architecture

- Android Java Activity: UI, input/history, scrolling output, file picker, lifecycle, and interactive forwarding.
- Rust `cdylib` through JNI: tokenize commands, validate the allowlist, and normalize arguments; do not execute a shell.
- Python/Chaquopy: call the fork's Click/Typer app and forward stdout/stderr/input to the terminal UI.
- Android Keystore: `AndroidTokenStore.java` holds the AES key; the Android Python OAuth adapter calls only the Java class API. Session metadata remains in the app's private data area.
- Disable the fork's background auto-update in the app. Do not spawn the keep-alive process in the Android MVP.

## Acceptance criteria

1. `cargo test` passes parsing, quoting, allowlist, and arbitrary-shell-command rejection cases.
2. The Rust `cdylib` compiles for Android ARM64.
3. Gradle builds a debug APK with embedded Python/CLI and JNI library.
4. The APK contains no OAuth keys/tokens; the manifest requests only the necessary network permission.
5. An offline `colab version`/`help` smoke test runs and displays the exact fork version.
6. Do not claim a real Colab/T4 run or device verification of the APK without corresponding results.
